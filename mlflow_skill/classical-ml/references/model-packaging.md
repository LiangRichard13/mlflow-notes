## 1. Why Packaging Matters

Every logged MLflow model is a directory that MLflow treats as a self-contained artifact. When you serve it (`models serve`) or batch-score it (`models predict`), MLflow reads three things from that directory:

1. **Signature** — what inputs/outputs the model accepts → server-side validation
2. **Dependencies** — what Python packages to install → env rebuild
3. **Code** — how to load and call the model → instantiation

If any of these is wrong or incomplete, you get cryptic errors at serve time. The fix is always in `log_model` arguments, not in the serving infrastructure.

## 2. Signature — Input/Output/Params Schema

A signature is a `ModelSignature(inputs=Schema(...), outputs=Schema(...), params=ParamSchema(...))`. MLflow stores it in `MLmodel` and validates requests against it at serve time.

### Inferred (most common)

```python
from mlflow.models import infer_signature

signature = infer_signature(
    X_train,
    model.predict(X_train),       # predictions on the training data
)
mlflow.sklearn.log_model(model, name="wine", signature=signature)
```

`infer_signature` looks at column names, dtypes, and shapes. If your model supports `predict_proba`, also pass `params={"threshold": 0.5}` to declare a parameter:

```python
signature = infer_signature(
    X_train,
    model.predict(X_train, threshold=0.5),   # signature records the threshold param
    params={"threshold": 0.5},
)
```

### Explicit (for full control)

```python
from mlflow.models import ModelSignature
from mlflow.types.schema import Schema, ColSpec, ParamSchema, ParamSpec

input_schema = Schema([
    ColSpec(name="fixed_acidity", type="double"),
    ColSpec(name="volatile_acidity", type="double"),
    ColSpec(name="quality", type="long"),   # if including target in inputs
])
output_schema = Schema([ColSpec(type="long")])
param_schema = ParamSchema([ParamSpec(name="threshold", type="double", default=0.5)])

signature = ModelSignature(inputs=input_schema, outputs=output_schema, params=param_schema)
```

### Supported column types

- `"double"` (float64), `"float"` (float32)
- `"long"` (int64), `"int"` (int32)
- `"string"`
- `"boolean"`
- `"binary"` (base64-encoded bytes)
- `"datetime"` (ISO 8601 strings at serve time)

### Why signature matters at serve time

With signature:
- Server accepts the documented schema
- Type coercion happens automatically (`"1.0"` → `1.0` if schema says double)
- Missing/wrong columns → `400 DataFrame column not found`

Without signature:
- Server may accept any shape → silent downstream errors
- No type coercion → you handle raw types yourself

## 3. Dependencies — Three File Formats

MLflow can write three different dependency files alongside the model. Pick based on your environment:

| File | Use when | Generated by |
|---|---|---|
| `requirements.txt` | Pip-only environments (most common today) | Auto, unless `conda_env` is passed explicitly |
| `conda.yaml` | Conda-managed environments | Auto, when `conda_env=` passed (or by default in older MLflow) |
| `python_env.yaml` | MLflow 2.x unified format, points to either conda or pip | Auto, alongside conda |

By default in MLflow 3, **`requirements.txt` is generated automatically** and `models serve --env-manager conda` will use it.

### Adding extra dependencies

```python
mlflow.sklearn.log_model(
    model, name="wine",
    extra_pip_requirements=["xgboost==2.0.0", "shap>=0.42"],
)
```

`extra_pip_requirements` is the safe way to add anything MLflow didn't auto-detect (e.g., `shap` for SHAP-bound models).

### Inspecting what was captured

```python
from mlflow.models import get_model_info
info = get_model_info("models:/WineQualityClassifier/3")
print(info.flavors)             # dict of flavor-specific config
# or read the directory directly:
# cat MLmodel | grep -A5 requirements
```

Or via CLI:
```bash
mlflow artifacts download --artifact-path wine -d ./wine_model
cat ./wine_model/requirements.txt
```

### Pinning vs floating versions

- `pip install mlflow` (floating) is fine for the captured model itself (MLflow itself is in the runtime, not in the model env)
- Pin your model's dependencies (`scikit-learn==1.5.1`) so serve builds the same env

## 4. Input Example — Tiny Sample Payload

```python
mlflow.sklearn.log_model(
    model, name="wine",
    signature=signature,
    input_example=X_train.head(3),      # 3 rows is the convention
)
```

MLflow writes `input_example.json` (for human inspection) and `serving_input_example.json` (the exact payload the server expects).

Test that your input example actually works at serve time:
```bash
mlflow models predict -m <uri> -i ./wine_model/serving_input_example.json -o /tmp/out.json -t json
```

If this works, real clients sending the same shape will work.

## 5. `models_from_code` — Avoid Pickle

> Pickling has known issues across Python versions, security risks, and brittle coupling to your training codebase. MLflow 2.18+ supports `models_from_code`: bundle a `predict.py` with the model instead of pickling.

### Pattern

```python
# /path/to/training/predict.py
import mlflow.pyfunc
import pandas as pd
import joblib

class WineClassifier(mlflow.pyfunc.PythonModel):
    def load_context(self, context):
        # Load any heavy artifacts here
        self.model = joblib.load(context.artifacts["model_path"])

    def predict(self, context, model_input: pd.DataFrame, params=None) -> pd.Series:
        threshold = (params or {}).get("threshold", 0.5)
        proba = self.model.predict_proba(model_input)[:, 1]
        return pd.Series((proba >= threshold).astype(int))
```

Then log it (no `python_model=` argument):
```python
mlflow.pyfunc.log_model(
    artifacts={"model_path": "wine_rf.joblib"},   # a file in your training dir
    code_paths=["predict.py"],                     # tells MLflow to bundle this
    name="wine-classifier",
    signature=signature,
    input_example=X_train.head(3),
)
```

At load time, MLflow reads `code/predict.py` and instantiates `WineClassifier` fresh — no pickle.

### When to use

- **Always**, if you can: avoid pickle entirely
- **Must**, if:
  - Model class is defined in `__main__` (not importable)
  - Your code uses lambdas, generators, or local functions
  - Python version at serve time ≠ Python at train time

## 6. `infer_pip_requirements` — What Goes in requirements.txt

```python
from mlflow.models import infer_pip_requirements

reqs = infer_pip_requirements(
    model_uri="models:/WineQualityClassifier/3",
    inference_template="predict",
    conda_env=None,                  # ignore conda
)
for r in reqs:
    print(r)
```

This is the same logic MLflow uses to write `requirements.txt` during `log_model`. Use it to audit or replicate the env outside MLflow:

```bash
pip install -r <(python -c "from mlflow.models import infer_pip_requirements; print('\n'.join(infer_pip_requirements('models:/WineQualityClassifier/3')))")
```

## 7. Environment Variables at Log Time

By default, MLflow captures every environment variable currently set and writes them to `environment_variables.txt` in the model directory. At load time, the server rehydrates them.

```python
# Disable if you don't want this (e.g., secrets leaked into artifacts)
import mlflow.models
mlflow.models.set_model(model)   # context, not relevant for log-time setting
```

Or pass the env var:
```bash
MLFLOW_RECORD_ENV_VARS_IN_MODEL_LOGGING=false mlflow sklearn log_model ...
```

Or programmatically:
```python
import os
os.environ["MLFLOW_RECORD_ENV_VARS_IN_MODEL_LOGGING"] = "false"
```

**Best practice**: don't rely on env vars for production configs; pass via the `params` argument of `predict()` so they're visible in the request payload.

## 8. Custom `predict.py` for Complex Models

For models that need heavy preprocessing, postprocessing, or feature engineering that doesn't fit in a single pickle:

```python
# predict.py
import mlflow.pyfunc
import pandas as pd
import numpy as np
from sklearn.preprocessing import StandardScaler
import joblib

class FullPipeline(mlflow.pyfunc.PythonModel):
    def load_context(self, context):
        self.scaler = joblib.load(context.artifacts["scaler"])
        self.model = joblib.load(context.artifacts["model"])
        self.feature_order = open(context.artifacts["feature_order"]).read().splitlines()

    def predict(self, context, model_input: pd.DataFrame, params=None):
        # Ensure column order matches training
        missing = set(self.feature_order) - set(model_input.columns)
        if missing:
            raise ValueError(f"Missing features: {missing}")
        X = model_input[self.feature_order]
        X_scaled = self.scaler.transform(X)
        return self.model.predict(X_scaled)
```

```python
# Log it
mlflow.pyfunc.log_model(
    python_model=FullPipeline(),
    artifacts={
        "scaler": "scaler.joblib",
        "model": "model.joblib",
        "feature_order": "feature_order.txt",
    },
    code_paths=["predict.py"],   # use models_from_code
    name="full-pipeline",
)
```

## 9. Pitfalls

1. **No signature + serve returns wrong shape**: add `infer_signature(X_train, model.predict(X_train))` and re-log.
2. **Custom class pickled, then class definition drifted**: load fails. Switch to `models_from_code`.
3. **Missing dep in `requirements.txt`**: serve fails with `ModuleNotFoundError` mid-request. Add via `extra_pip_requirements=[...]` and re-log.
4. **`input_example` doesn't match signature**: MLflow warns at log time; serve may still accept it but with wrong coercion. Always pass `input_example=X.head(3)` where `X` is the same data you passed to `infer_signature`.
5. **Conda env rebuild slow**: every `models serve` (first time) builds a fresh env with `requirements.txt`. Use `--env-manager local` to skip if you've installed the deps already.
6. **Env vars leaking into model artifact**: secrets end up in `environment_variables.txt`. Disable via `MLFLOW_RECORD_ENV_VARS_IN_MODEL_LOGGING=false`.
7. **Python version mismatch**: training on 3.11, serving on 3.9 → many pickles fail to load. Either pin Python via Docker or use `models_from_code`.
8. **`extra_pip_requirements` doesn't override captured ones**: use `pip_requirements=None` to fully override.
9. **`predict()` in custom pyfunc doesn't accept `params`**: you must include `params=None` in the signature, even if unused, or serve-time calls with `params={...}` fail.
